# 회사 PC 실행 안내 — HOMSelf HOMS 연동 1차 버전

## 현재 가능한 것 / 아직 필요한 것

- 기본 실행: 승인 대기 목록 조회와 서버 연결 점검. **HOMS 접속·불출 없음**.
- 실제 모드: 수동 로그인/자재 검색/담당자 선택 → 코드·담당자 ID·수량 검증 → 불출 버튼 및 확인 팝업 클릭 → 사람이 HOMS 결과 확인 → 완료 기록.
- 1회 실행에 자재 1항목만 처리하는 **현장 검증용 반자동 버전**입니다. 무인 연속 자동 불출 버전이 아닙니다.
- HOMS 화면의 실제 DOM 및 결과 조회는 여기서 검증하지 않았습니다. `selectors.example.json`의 빈 값과 열 번호를 현장에서 확정해야 합니다. 검증 전에는 실제 모드가 중단됩니다.
- 원본 프로그램의 랜덤 담당자, 적정재고 초과분 출고, 강제 readonly 해제, 무조건 Enter, 로그인 비밀번호 하드코딩은 사용하지 않습니다.

## 1. 설치

1. ZIP을 회사 PC의 전용 폴더에 압축 해제합니다. 원본 프로그램과 섞거나 덮어쓰지 마세요.
2. Python 3.11 이상(기존 3.14 사용 가능), Chrome이 필요합니다.
3. `setup.cmd`를 실행합니다. Selenium 설치 및 Chrome 드라이버 준비에 회사 네트워크 허용이 필요할 수 있습니다. 정책 제한을 우회하지 마세요.
4. 생성된 `config.json`의 `server_url`을 **새 서버가 실제 배포된 주소**로 설정합니다. 기존 배포에 새 API가 없으면 HTTP 404로 중단되는 것이 정상입니다.
5. Windows 사용자 환경변수에 `HOMSELF_WORKER_TOKEN`을 설정합니다. 서버의 `WORKER_TOKEN`과 같은 값입니다. 새 터미널을 열어야 반영됩니다.

HOMS 비밀번호는 저장하지 않습니다. 실제 모드에서 열린 브라우저에 직접 로그인합니다.
인증키를 GitHub/채팅에 붙여넣지 마세요. 관리자용과 키오스크용, PC 처리기용 키는 서로 다릅니다.

## 2. 비불출 점검

`check.cmd` 실행. 서버 응답·전체 정지 여부·승인 목록을 출력합니다. 요청을 점유하거나 HOMS를 열지 않습니다.
서버 기본 상태는 전체 정지입니다. 이 단계에서는 해제할 필요가 없습니다.

## 3. HOMS 선택자 검증 (필수)

`selectors.json`에서 아래 값을 실제 HOMS 화면과 대조하세요. CSS는 `.class`, `#id` 방식이고 XPath 값은 별도 `_xpath` 키입니다.

| 값 | 필요한 확인 |
|---|---|
| stock_rows | 조회된 자재 행을 가리키는 CSS |
| code_cell_index / stock_cell_index | 자재코드/현재재고 td 열 번호(1부터) |
| selected_receiver_id_css | 선택 완료된 담당자의 고유 ID가 들어 있는 유일한 요소 |
| selected_receiver_name_css | 선택 완료된 담당자 이름 요소(검색어 입력창 아님) |
| popup_material_code_css | 불출 팝업에서 실제 선택된 자재코드 요소 |
| second_confirm_css | 실제 두 번째 확인 버튼(무조건 Enter 사용 안 함) |
| manager_ids | 매니저 이름 → 실제 HOMS 담당자 ID 매핑, 예: 이름 문자열을 키로 하고 실제 ID 문자열을 값으로 입력 |

검색창에 입력된 이름만으로 담당자를 확인하지 않습니다. 정확한 고유 ID가 필요합니다.
요소는 기본적으로 표시된 유일한 요소를 찾습니다. ID가 hidden input에만 있다면 어댑터를 현장 DOM에 맞게 보완해야 합니다.
현재재고는 `123` 또는 `1,234` 형식만 허용합니다. `재고(3)` 등 다른 형식은 임의 숫자 추출 대신 중단합니다.
자재코드가 같은 행이 여러 개(창고/로트 구분)거나 다른 페이지에 있으면 임의 선택하지 않습니다.
모든 값을 확인하기 전 `validated_on_company_pc`를 true로 바꾸지 마세요. 이 플래그는 검증 자체를 대신하지 않습니다.

## 4. 실제 1건 검증

1. 실제 반출할 소량 자재 1개를 HOMSelf로 요청합니다. 테스트를 위해 가짜 불출 기록을 만들지 마세요.
2. 관리자 화면에서 매니저·자재코드·수량을 확인하고 승인합니다.
3. 선택자가 검증된 뒤 처리 허용을 누르고 `live_one.cmd`를 실행합니다.
4. Chrome에서 직접 로그인 → 안내에 따라 자재코드 검색 → 담당자 선택.
5. 콘솔에 매니저 이름·자재코드·수량을 그대로 입력해야 실제 불출을 시작합니다.
6. 실제 불출내역을 보고 불출번호 또는 시각 등의 근거를 입력합니다. 팝업이 닫혔다는 사실만으로 확인하지 마세요.
7. HOMSelf 관리자 화면과 HOMS 내역이 일치하는지 확인합니다. 매 실행 1항목만 처리하고 종료합니다.

## 중단/네트워크 오류

- 재실행한다고 같은 항목을 자동 재불출하지 않습니다. `runtime/journal.sqlite`를 삭제하지 마세요.
- 준비/불출 중 오류는 서버에 확인 필요로 보냅니다. 서버 연결 자체가 끊겼다면 준비 중/불출 중으로 남아 전체 큐를 막을 수 있습니다.
- 관리자에서 **전체 일시정지**, 모든 PC 처리기 종료, HOMS 실거래 조회 순서로 진행하세요.
- 실제 완료면 `실제 불출 완료 확인`, 미불출이 확실할 때만 `미불출 확인 → 재승인 대기`를 선택하고 근거를 적습니다.
- 후자의 경우 PC에서 `.venv\Scripts\python.exe worker.py --reconcile 항목번호`로 로컬 차단도 수동 해제한 뒤 재승인합니다.
- 결과가 불명확하면 미불출로 판정하지 말고 확인 필요로 유지하세요. 실제 부분 불출이 발생했다면 수량 정정 후 새 요청을 만드는 절차를 관리자가 별도 수행해야 합니다.

## 비공개 DB 백업

Windows 사용자 환경변수:

- `HOMSELF_ADMIN_TOKEN`: 서버 ADMIN_TOKEN과 동일
- `HOMSELF_BACKUP_GITHUB_TOKEN`: `HOMSelf-data` 한 저장소에만 Contents 읽기/쓰기 권한이 있는 GitHub 토큰. HOMS/서버 인증키와 별개.

`backup.cmd` 실행 → 서버 스냅샷 다운로드 → SQLite 무결성 확인 → private 확인 → GitHub 업로드.
실제 인증키는 파일에 포함하지 않았습니다. 토큰 생성/저장은 사용자 PC에서 직접 하세요.
백업 실패는 불출 성공/실패를 바꾸지 않습니다. 서버 DB가 원본이며 다음 백업 전에 PC 로컬 복사본도 남습니다.
이 도구는 실행할 때만 백업합니다. 자동 일정은 등록하지 않았습니다.

## 테스트(실제 HOMS 미사용)

`.venv\Scripts\python.exe -m unittest -v test_worker.py`

모의 어댑터로 begin 응답 유실 시 클릭 0회, complete 응답 유실 시 재클릭 차단을 확인합니다.
